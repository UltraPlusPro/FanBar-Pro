FanBar Pro 1.5.6 源码说明
============================

版本：FanBar Pro 1.5.6（CFBundleVersion = 156）
Bundle ID：local.fanbar.app（未变，特权 Helper 的客户端鉴权依赖它）
可执行文件名：FanBar Pro（.app 与 Contents/MacOS/ 均为该名）
架构：arm64　最低系统：macOS 15.8（见 App/Info.plist 与 Package.swift）
签名：Local QA Code Signing（本地证书，无 Team ID）

一、本包内容
------------
- Sources/FanBar/            主程序（AppKit / SwiftUI）
- Sources/FanBarShared/      共享层（本地化、诊断、协议、自身签名读取）
- Sources/FanBarHelper/      特权 Helper
- Sources/FanBarCLI/         命令行工具 fanbar
- Sources/FanBarWidget/      Widget 数据层
- WidgetExtension/FanBarWidgetExtension.xcodeproj   Widget 的 Xcode 工程
- FanBarPro.xcodeproj        主工程的 Xcode 工程
- Tests/                     单元测试
- scripts/package-app.sh     唯一的构建入口：编译 + 组装 + 逐个签名 + 校验
- 脚本/构建-FanBar-Pro.command   本地包装（固定签名身份后调用 package-app.sh）
- App/Info.plist             版本与 bundle 元数据
- App/local.fanbar.helper.plist  嵌入的 LaunchDaemon plist（SMAppService 路径）
- docs/helper-lifecycle-1.5.6.md  Helper 生命周期与注册方式取舍（重要）
- Assets/、Resources/        图标与资源

二、构建方式（本机已验证）
--------------------------
    cd <本目录>
    ./一键编译.command            # 或下面这条等价命令

    export FANBAR_SIGN_IDENTITY="Local QA Code Signing"
    export FANBAR_ARCHS=arm64
    export FANBAR_DISABLE_SWIFTPM_SANDBOX=1
    export FANBAR_APP_OUTPUT="build/FanBar Pro.app"
    zsh scripts/package-app.sh

    产物：build/FanBar Pro.app（1.5.6 / 156，arm64）

说明：
- 1.5.6 起**不再使用 ad-hoc 签名**。ad-hoc 签名的 app 没有 Team ID，
  SMAppService 会为 helper 写下一条任何代码都满足不了的启动约束
  （`launchctl print` 里 `LWCR … cdhash "$in" = [ ]`、`ccat = 0`），
  于是每次开机约 35 秒后 helper 被 SIGKILL：这就是「开机不唤起」的根因。
  改用固定的本地证书后，app 与 helper 的 Authority 与 designated requirement
  一致且跨重启稳定：
      Authority=Local QA Code Signing
      designated => identifier "local.fanbar.app" and certificate leaf = H"bb99…c123"
      designated => identifier "local.fanbar.helper" and certificate leaf = H"bb99…c123"
- 有 Developer ID 时把 FANBAR_SIGN_IDENTITY 换成
  "Developer ID Application: ..."；此时脚本会自动加 --options runtime --timestamp，
  代码也会自动回到 SMAppService 注册路径。
- 首次构建需要联网拉 Sparkle 2.9.6（Package.resolved 已锁定）。

三、校验（本机已跑通）
----------------------
    codesign -dv --verbose=4 "build/FanBar Pro.app"
    codesign -dv --verbose=4 "build/FanBar Pro.app/Contents/Library/LaunchServices/local.fanbar.helper"
    codesign -d -r- "build/FanBar Pro.app"                       # 看 designated requirement

注意：**不要**用 `codesign --verify --deep --strict` 校验整个 app。
Sparkle.framework 的 `Versions/B` + `Versions/Current` 软链布局会让 codesign 报
"bundle format is ambiguous" 并中止深度遍历。package-app.sh 已改为逐个校验嵌套
组件（每个结果都无歧义），最后再对 app 做一次非 deep 的 `--verify --strict`：

    for p in "Contents/MacOS/FanBar Pro" \
             "Contents/MacOS/FanBarDiagnostics" \
             "Contents/Helpers/fanbar" \
             "Contents/Library/LaunchServices/local.fanbar.helper" \
             "Contents/PlugIns/FanBarWidget.appex"; do
        codesign --verify --strict --verbose=1 "build/FanBar Pro.app/$p"
    done
    codesign --verify --strict --verbose=2 "build/FanBar Pro.app"

`spctl -a` 对本机构建会输出 `rejected / origin=Local QA Code Signing`：
本地证书未经过 Apple 公证，这是预期结果，不影响本机运行（Gatekeeper 只对带
com.apple.quarantine 的下载物生效）。

五、1.5.6 关键改动速览（详见 变更说明-1.5.6.txt）
--------------------------------------------------
1. 【P0】root Helper 开机不唤起：统一签名 + 幂等清理同 label 旧注册 + RunAtLoad/
   KeepAlive + 启动自愈。根因、证据、取舍见 docs/helper-lifecycle-1.5.6.md。
2. 【P0】托盘与设置温度不一致：菜单栏、面板、Widget 统一显示「温控曲线输入温度」
   （与设置里的「当前」同源），最热核只出现在 tooltip 与诊断里。
3. 【P1】Helper 客户端鉴权：从「只比 bundle id」升级为「bundle id + 叶证书 SHA-1」，
   恢复 0.9.0 的强度（0.9.0 是无 team 直接拒绝，1.1.5 放宽成了可伪造的 identifier）。
4. 版本号 1.5.6 / 156；构建脚本修名（原 脚本/构建-FabBar-Pro.command 拼写错误，
   导致 一键编译.command 直接失败）。
